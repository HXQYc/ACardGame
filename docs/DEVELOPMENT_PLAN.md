### P02 牌型规则（当前任务）

建议顺序：

1. game_types.h：定义 HandType/牌型描述，最小字段包括类别、张数、最高点数；精确命名和失败表示先讨论。
2. hand_rules：建立本游戏顺序 5～K、A；2/3/4及非法点数不能参与合法牌型，不直接比较 Rank 枚举值。
3. 识别单牌、对子、顺子、连对、三张炸弹、四张雷；输入顺序不影响结果；空牌、不合法牌和重复实体牌不能识别为合法出牌。
4. 比较牌型：同类严格更大；顺子同张数、连对同对数；雷高于炸弹、炸弹高于普通牌型；花色不比大小。
5. 身份牌 A 优先：根据完整本人手牌与选择牌计算；三人只优先黑桃 A，四人两张黑 A；支持拆牌。
6. 查询有无合法管牌组合，为拒绝给风和 allowed_actions 服务；必须计入身份牌优先限制，不能只比较点数。

边界：识别不改变手牌、不决定轮到谁；管牌比较不处理房间。是否采用 optional、错误枚举或结果结构在接口讨论时选定，玩家错误不能一律抛异常。

完成标志：模块能编译，规则样例逐项评审；手工验证与自动验证分别记录。新增 .cpp 加入 acard_game，库依赖不扩散到网络/JSON。

### P03 阵营与结算

文件：game_types、settlement.h/.cpp，初始化相关逻辑可由 game 调用。

- 基于初始手牌确认阵营；四人两张黑 A 同一人时标记一对三，其余为二对二；三人为一对二。
- 阵营与对抗类型在本局不变化，不因打掉身份牌重新判定。
- settlement 接收参赛信息及完整名次，按 RULE.md 全部表格结算，不依赖 socket 或房间。
- 正常结果与中止结果分开；不擅自加入积分、筹码或进贡。

验收：四人二对二六个组合、黑户四个名次、三人三个名次均有明确结果；拒绝重复/缺失名次等无效内部输入。

### P04 牌局状态机与视图

文件：game_state.h、game.h/.cpp、game_view.h/.cpp。

顺序：

1. 创建合法初始牌局：3/4份手牌、总牌组完整且无重复、初始阵营、红桃5先手、revision=1。
2. 统一操作入口，区分参数/阶段/行动者/牌归属/牌型/优先A/大小错误；全部通过后才提交变化。
3. 普通回合：领出禁过、跟牌与过牌、新牌清过牌记录、全过归最后出牌者。
4. 出完记录及跳过；只剩一人立即末名与结算。
5. 接风选择、轮询、全部同意、第一个拒绝、B管牌取消义务、B过牌跳到拒绝者强制管牌。
6. B不申请直接过牌的 following_passes：保存原接风受益者，全过归B；有人出新牌取消旧上下文，出完建立新上下文。
7. 个人视图：本人手牌/阵营、他人数量、公开牌与身份、唯一行动者、允许操作、公开接风回答；结算只公开阵营名次。
8. 操作变化递增revision；中止不产生胜负、不公开隐藏信息。

游戏位置固定，不存 ConnectionId/PlayerId；房间负责映射。AI 将来读取个人视图，调用相同操作入口，不直接改状态。

验收：可以无网络走完整三/四人局；非法操作前后状态相同；接风各分支闭合；视图无秘密泄漏。接口设计完成并不等于这些行为已验收。

### P06 网络与协议基础

文件：cmake/Dependencies.cmake、network/*、protocol/*、app 配置与入口。标识头文件按需创建；日志先在启动处初始化，分帧先在网络内部实现。

- 固定 Asio/JSON/spdlog 版本，按真实依赖配置目标，外围可先归入 acard_server，复用或隔离需要时再拆库；第三方缓存仅在构建目录。
- 值类型标识不引入业务依赖。
- 长度帧：4字节大端、UTF-8字节长度、半包/多包、长度/深度/发送队列限制与帧超时。
- 单连接异步读写、一个写操作、连接所有权及取消回调；单线程 io_context。
- 定义类型化消息、统一信封、卡牌编号、错误映射；握手/序号/心跳/超时。
- 按 BUILD.md CLI 配置优先级、固定端口、日志目录、错误退出码。
- 建立开发用TCP请求工具或集成样例，多个连接无需Godot也能验证。

实现协议前必须讨论 JSON 严格预校验成本：当前规范要求原始数字token、重复键、UTF-8与语法检查。可以保留，也可经用户同意简化并同步规范；不能实现库默认行为后声称满足严格规范。

完成：真实TCP可完成hello/ping和错误响应；分帧、消息序号、异常关闭有验证；尚不声称游戏联机完成。

### P07 会话、房间与开局

文件：room.h/.cpp、server_app.h/.cpp。会话数据和映射先由 ServerApp 保存，一个默认 Room 由应用持有；RoomManager 与 SessionManager 延后到实际需要。

- 会话由握手成功创建，绑定连接与临时身份；昵称仅展示。
- 默认房间自动加入、最小空座位、人数3/4、全部准备、房主开始。
- 等待中成员变化清准备，房主按最小座位交接；无变化ready响应后补同revision快照。
- 开局固定名单，座位升序映射position；上一局第一名仍在则发牌从他起，否则随机当前成员。
- 房间创建/持有/释放Game，不绕过Game接口改手牌。

验收：多连接入房/准备/开始；满员、游戏中加入、非房主、过期revision被拒；三/四人都收到自己的初始视图。默认房间为空仍保留。

### P08 服务端完整闭环

- 路由四种牌局操作，连接身份转本局位置；game_id/revision防旧请求。
- 响应先于状态通知，逐玩家投影；最后操作后按最终状态→结算→等待房间顺序发送。
- 普通成员断线/离开中止，保留上一局有效第一名；状态和会话清理幂等。
- 所有者token、优先入房、已绑定所有者断线、远程关闭权限；独立服务器房主无关闭权。
- 所有关闭路径统一事务，先取最终数据和排队通知，再释放牌局；不重复中止或房主交接。
- 事件循环不阻塞，心跳、慢连接、限速和超时落实。

完成：开发用多连接工具可玩完整三/四人局并重新准备下一局；主要接风分支、断线和关闭实际运行；服务器可独立启动。用工具验证的效果与正式Godot联调分开记录。
